## 2025-02-23 - Critical IDOR and Missing Auth in Chat Update
**Vulnerability:** The `PUT /api/research/chat/update_name/[id]` endpoint lacked authentication checks and did not verify that the chat belonged to the requesting user (IDOR). Additionally, it was attempting to update a non-existent `title` field instead of the correct `name` field.
**Learning:** API endpoints for resource modification must explicitly verify ownership (`userId` scoping) in database queries. Relying on obscure field names (like `title` vs `name`) can hide bugs where updates silently fail or modify wrong data. Mongoose `strict: true` (default in v6+) silently ignores invalid fields, masking the bug.
**Prevention:** Always use `getAuthenticatedUser()` and include `{ userId: user.id }` in `findOneAndUpdate` or similar queries. Verify schema definitions against update payloads. Ensure tests cover both authentication and authorization (ownership) scenarios.
